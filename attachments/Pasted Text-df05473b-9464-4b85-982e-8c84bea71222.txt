Master Prompt: "My Offers" — Grocery Offer Search & Notification App

Role: You are an expert full-stack developer, data engineer, and brand designer. Build a cross-platform mobile app called "My Offers" that aggregates grocery offers from every available online source — store websites, social networks, local groups, and digital flyers — within a user-specified city or precise area. The system must crawl, parse, deduplicate, and index offers so no offer is missed. Users can search manually, receive push notifications for priority items/areas, and see priority items/areas pinned at the top. Additionally, generate a professional app icon using your own image generation capability.

1. Core Requirements

· Comprehensive data acquisition: Crawl all accessible grocery store websites, social media platforms, local community groups, and digital flyers for the selected city/area.
· No offer missed: Multi-source crawling, frequent scheduling, fallbacks (APIs, RSS, manual submissions).
· Location-based search: City or precise area (GPS or manual).
· Manual search: Filters by item, category, store, price, distance, date, source.
· Push notifications: Instant alerts for new offers matching user's priority items/areas.
· Priority items and areas: Pinned to the top of all lists and search results.
· Most recent first: Sorted by recency with timestamps.
· Deduplication: Merge identical offers from multiple sources.
· Admin & moderation: Review, edit, approve crawled offers.

2. Data Sources & Crawling Strategy

2.1 Target Sources

· Grocery store websites: Carrefour, Tesco, Walmart, Lulu, Spinneys, and local chains.
· Social networks:
  · Facebook: Public pages, groups, Marketplace, local buy/sell groups.
  · Instagram: Store accounts, hashtags (#grocerydeals, #cityname).
  · Twitter/X: Store handles, local deal accounts, hashtags.
  · TikTok: Store accounts, local deal creators.
  · Telegram/WhatsApp: Public channels/groups (where API allows).
· Digital flyers & aggregators: Flipp, Reebee, store flyer pages.
· Local forums & classifieds: Craigslist, Nextdoor, local subreddits.
· Manual submissions: Users/store owners can submit offers.

2.2 Crawling Architecture

· Crawler microservices: One per source type (web, Facebook, Instagram, etc.).
· Scheduler: Airflow or Cron (every 15 min social, hourly web).
· Queue: Redis + Bull (Node) or Celery (Python).
· Parsers: Extract item, price, discount, store, area, dates, image, source URL.
· Normalization: Standardize names, categories, currencies, area codes.
· Deduplication: SHA256 + fuzzy matching (Levenshtein, TF-IDF).
· Storage: Raw in MongoDB/S3; structured in PostgreSQL.
· Legal & Ethical: Respect robots.txt, API terms, rate limits; use official APIs; anonymize user data.

2.3 Social Media Integration

· Facebook Graph API: Public pages/groups (with app review).
· Instagram Graph API: Business accounts and hashtags.
· Twitter API v2: Filtered stream for keywords + location.
· TikTok Research API: Public content (if approved).
· Fallback: Playwright headless browsers for public pages.

4. Data Models (PostgreSQL)

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  firebase_uid VARCHAR(255) UNIQUE NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  name VARCHAR(255),
  fcm_token TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE areas (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  city VARCHAR(255) NOT NULL,
  latitude DECIMAL(9,6),
  longitude DECIMAL(9,6),
  radius_km DECIMAL(5,2) DEFAULT 5.0,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE stores (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  address TEXT,
  latitude DECIMAL(9,6),
  longitude DECIMAL(9,6),
  logo_url TEXT,
  area_id INT REFERENCES areas(id),
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE sources (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  type VARCHAR(50) NOT NULL,
  base_url TEXT,
  area_id INT REFERENCES areas(id),
  crawl_frequency_minutes INT DEFAULT 60,
  last_crawled_at TIMESTAMP,
  active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE offers (
  id SERIAL PRIMARY KEY,
  store_id INT REFERENCES stores(id),
  area_id INT REFERENCES areas(id),
  source_id INT REFERENCES sources(id),
  item_name VARCHAR(255) NOT NULL,
  category VARCHAR(100),
  price DECIMAL(10,2),
  original_price DECIMAL(10,2),
  discount_percent INT,
  description TEXT,
  image_url TEXT,
  source_url TEXT,
  start_date DATE,
  end_date DATE,
  is_verified BOOLEAN DEFAULT FALSE,
  dedup_hash VARCHAR(64) UNIQUE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE priority_items (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  item_name VARCHAR(255) NOT NULL,
  category VARCHAR(100),
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE priority_areas (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  area_id INT REFERENCES areas(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE notification_log (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id),
  offer_id INT REFERENCES offers(id),
  sent_at TIMESTAMP DEFAULT NOW()
);
```

5. API Endpoints (REST)

· Auth: POST /api/auth/register, POST /api/auth/login
· Users: GET /api/users/me, PUT /api/users/me
· Areas: GET /api/areas?city=..., GET /api/areas/nearby?lat=...&lng=...&radius=...
· Offers: GET /api/offers?areaId=...&search=...&category=...&sort=recent, GET /api/offers/priority?userId=..., GET /api/offers/:id, POST /api/offers
· Priority: POST /api/priority/items, DELETE /api/priority/items/:id, POST /api/priority/areas, DELETE /api/priority/areas/:id
· Notifications: POST /api/notifications/register-token, POST /api/notifications/test
· Crawler Admin: GET /api/sources, POST /api/sources, PUT /api/sources/:id, POST /api/crawl/trigger/:sourceId

---

6. Crawling & Aggregation Workflow

1. Scheduler triggers jobs based on crawl_frequency_minutes.
2. Crawler fetches data via Playwright/Scrapy/APIs with proxy rotation.
3. Parser extracts and normalizes fields.
4. Deduplication computes dedup_hash; updates or inserts.
5. Area mapping via geocoding.
6. Notification trigger: On new insert, match users and push via FCM/Expo.
7. Indexing: Update full-text search.
8. Monitoring: Dashboard for crawl success, errors, and coverage gaps.

---

7. Push Notification Logic

· Trigger: New offer inserted or updated with new price/discount.
· Matching: item_name matches priority items (fuzzy) OR category matches OR area_id in priority areas.
· Send: Expo Notifications with user's FCM token.
· Payload: { title: "New Offer on My Offers!", body: "${item_name} at ${store_name} for ${price}", data: { offerId } }
· Throttling: Max 1 notification per user per offer; log in notification_log.
